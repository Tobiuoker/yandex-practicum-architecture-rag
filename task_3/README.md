# Задание 3. Создание векторного индекса

## Модель эмбеддингов

Для построения векторных представлений используется:

`nomic-ai/nomic-embed-text-v1.5`

Основные параметры:

- размер вектора: 768;
- модель запускается локально через `sentence-transformers`;
- для документов используется префикс `search_document:`;
- для поисковых запросов используется префикс `search_query:`.

## База знаний

Источником служит подготовленная на предыдущем этапе папка:

```text
knowledge_base/
```

В индекс загружаются только эти документы. `terms_map.json` и `manifest.json` не индексируются.

## Разбиение на чанки

Документы разбиваются через `RecursiveCharacterTextSplitter`.

Параметры:

```text
chunk_size = 600 токенов
chunk_overlap = 80 токенов
```

Размер считается токенизатором embedding-модели.

Для каждого чанка сохраняются метаданные:

- исходный файл;
- заголовок документа;
- номер чанка;
- позиция начала чанка в документе.

## Векторная база

В качестве векторной БД используется **ChromaDB**, запущенная локально через Docker.

Коллекция:

```text
witcher_lore
```

Для поиска используется cosine similarity.

Скрипт построения индекса:

```text
build_index.py
```

Он:

1. загружает Markdown-документы;
2. разбивает их на чанки;
3. рассчитывает embeddings;
4. создает коллекцию ChromaDB;
5. загружает тексты, векторы и метаданные;
6. сохраняет статистику в `index_stats.json`.

## Статистика

Фактические результаты сохраняются в:

```text
index_stats.json
```

Пример:

```json
{
  "model": "nomic-ai/nomic-embed-text-v1.5",
  "embedding_dimension": 768,
  "documents": 516,
  "chunks": 972,
  "chunk_size_tokens": 600,
  "chunk_overlap_tokens": 80,
  "embedding_seconds": 20.43,
  "total_seconds": 29.72,
  "collection": "witcher_lore"
}
```

В отчет подставляются реальные значения после запуска `build_index.py`.

## Пример поиска

Запрос:

```text
Who is Alexander Santiago?
```

Поисковый запрос преобразуется в embedding:

```text
search_query: Who is Alexander Santiago?
```

После этого ChromaDB возвращает наиболее близкие чанки.

Пример результата:

```text
#1 similarity=0.801
Title: Alexander Santiago
Source: doc_0173.md
Chunk: 0
--------------------------------------------------------------------------------
<текст найденного чанка>

#2 similarity=0.719
Title: Alexander Santiago
Source: doc_0173.md
Chunk: 1
--------------------------------------------------------------------------------
<текст найденного чанка>

#3 similarity=0.681
Title: Alexander Santiago
Source: doc_0173.md
Chunk: 2
--------------------------------------------------------------------------------
<текст найденного чанка>

#4 similarity=0.651
Title: Alexander Santiago
Source: doc_0173.md
Chunk: 3
--------------------------------------------------------------------------------
<текст найденного чанка>

#5 similarity=0.651
Title: Alexander Santiago
Source: doc_0173.md
Chunk: 4
--------------------------------------------------------------------------------
<текст найденного чанка>
```

Для проверки поиска используется:

```bash
python -m task_3.search "Who is Alexander Santiago?"
```

## Результат

В результате создан локальный векторный индекс в ChromaDB, содержащий чанки базы знаний и их 768-мерные embeddings.

Код построения индекса находится в `build_index.py`, а фактическое количество чанков и время генерации сохраняются в `index_stats.json`.
