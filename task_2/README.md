# Задание 2. Подготовка базы знаний

## Исходные данные

В качестве предметной области используется **Witcher Wiki**:

`https://witcher.fandom.com/wiki/Witcher_Wiki`

Из вики автоматически загружаются страницы по основным категориям:

- персонажи;
- локации;
- существа;
- предметы;

Получение страниц выполняется через MediaWiki API.

## Очистка документов

Скрипт получает текст статей, удаляет служебную разметку, ссылки на источники и другие элементы, не относящиеся к содержанию статьи.

Обычный текст ссылок сохраняется. Например:

`[[Timeline#1248|1248]]`

превращается в:

`1248`

а содержимое ссылок-сносок `<ref>...</ref>` удаляется.

Каждая сущность сохраняется в отдельный Markdown-файл:

```text
knowledge_base/
├── doc_0001.md
├── doc_0002.md
├── ...
└── doc_0200.md
```

## Подмена терминов

Чтобы модель не могла отвечать по памяти о вселенной Ведьмака, именованные сущности автоматически заменяются на вымышленные.

Для генерации новых имен используется библиотека **Faker**.

Примеры:

```text
Hjalmar an Craite -> Alexander Santiago
Vilgefortz of Roggeveen -> Rodney Lewis
```

Подменяются именно именованные сущности: персонажи, города, государства, существа и другие уникальные названия.

Общие понятия вроде `city`, `human`, `kingdom`, `witcher` не заменяются, чтобы не искажать смысл текста.

Для одной и той же исходной сущности всегда используется одна и та же замена.

## terms_map.json

Все соответствия сохраняются в:

```text
terms_map.json
```

Пример:

```json
{
  "Hjalmar an Craite": "Alexander Santiago",
  "Vilgefortz of Roggeveen": "Rodney Lewis"
}
```

Этот файл используется только для подготовки и проверки базы и **не загружается в RAG-индекс**.

## Результат

На выходе получено:

- Очищенныe Markdown-документы;
- автоматически сгенерированный `terms_map.json`;
- `manifest.json` со связью исходных и преобразованных сущностей;
- скрипт `build_kb.py` для повторной сборки базы;
- финальная папка `knowledge_base/`, содержащая только анонимизированные документы.

В дальнейшем в RAG индексируется только:

```text
knowledge_base/*.md
```

Таким образом исходная вселенная остается логически целостной, но ключевые названия изменены, поэтому LLM не может надежно использовать знания о Ведьмаке из обучающей выборки и должна опираться на подготовленную базу знаний.
